Prise en main TontApp

Gérer une tontine de bout en bout : invitations, tours, encaissement des cotisations en espèces et journal d'audit. Chaque parcours a été filmé en conditions réelles, sur un téléphone Android et dans le navigateur.

F

L'argent reste hors de l'application. Les membres remettent leur cotisation au gestionnaire (espèces ou banque). TontApp tient le registre : le gestionnaire saisit le paiement, le valide après avoir vérifié la preuve, et chaque action est inscrite dans un journal infalsifiable.

Qui fait quoi

Mobile + web

Gestionnaire

Crée la tontine, invite les membres par code, l'active, gère les tours, relance les retardataires. Sur le web, il encaisse et valide les cotisations.

Mobile

Membre

S'inscrit avec son numéro (code OTP), rejoint une tontine avec un code d'invitation, suit le tour en cours et l'historique de ses versements.

Web

Administrateur

Supervise la plateforme : métriques de la semaine, liste de toutes les tontines, alertes (chaîne d'audit rompue, tours en retard, SMS en échec).

Démarrer en local

Prérequis : Docker, le SDK .NET 10 (installé dans ~/.dotnet), Node 20+, et pour le mobile le SDK Android avec un téléphone branché en USB (débogage USB activé). Toutes les commandes se lancent à la racine du dépôt.

make up
Démarre PostgreSQL (port 5433) et Redis (port 6380).
make api
Lance l'API sur http://localhost:5243 et applique les migrations. Laisser ce terminal ouvert.
make seed
Crée les comptes de démonstration et la « Tontine du Marche » (3 membres, en brouillon).
make dashboard
Lance le tableau de bord web sur http://localhost:3000.
make mobile
Redirige les ports du téléphone (adb reverse) et lance Metro pour l'application Android.
make otp TEL=+22670000010
En développement, les SMS sont simulés : cette commande affiche le code OTP envoyé à un numéro.
make reset
Efface toutes les données de développement pour repartir de zéro (arrêter l'API avant).

Un cycle complet, dans l'ordre

Le parcours en six scènes

Les scènes s'enchaînent : chacune part de l'état laissé par la précédente. Les points blancs sur les vidéos du téléphone montrent chaque toucher ; sur le web, le cercle rouge suit la souris.

1TéléphoneGestionnaire · 1 min 45

Se connecter et inviter des membres

  1. Parcourir les trois écrans de présentation, puis Commencer.
  2. Se connecter avec le compte d'Awa (70000002, Demo2026!).
  3. Ouvrir Tontine du Marche : statut Draft, 3 membres, cotisation de 10 000 FCFA par mois.
  4. Inviter des membres, puis Générer un code d'invitation. Le code à 6 caractères est valable 7 jours et peut être partagé via WhatsApp.
  5. Se déconnecter depuis Profil.

À retenir : un code fonctionne aussi après l'activation. Le nouveau membre attend alors la validation du gestionnaire, passe en dernier dans l'ordre des bénéficiaires et rattrape les cotisations des tours déjà ouverts (fonction ajoutée après le tournage).

2TéléphoneNouveau membre · 2 min 10

S'inscrire et rejoindre la tontine

  1. Créer un compte : nom, numéro, mot de passe (8 caractères minimum, une majuscule, un chiffre).
  2. Saisir le code OTP à 6 chiffres reçu par SMS (en développement : make otp TEL=…), puis Vérifier.
  3. Sur l'accueil vide, toucher l'icône Rejoindre une tontine (poignée de main).
  4. Entrer le code d'invitation de la scène 1 ; le nom affiché dans le groupe est pré-rempli.
  5. Fatou apparaît dans la tontine, qui compte maintenant 4 membres.

À retenir : le compte est rattaché au numéro de téléphone. Un même numéro ne peut rejoindre une tontine qu'une seule fois.

3TéléphoneGestionnaire · 1 min 46

Activer la tontine et gérer le tour

  1. Se reconnecter en tant qu'Awa et ouvrir la tontine.
  2. Activer la tontine puis confirmer. Il faut au moins 3 membres. Les inscriptions sont fermées et le tour n°1 s'ouvre avec Ibrahim comme bénéficiaire (ordre d'inscription).
  3. Le détail affiche la progression des paiements et le compte à rebours jusqu'à la fin du tour (30 jours pour une tontine mensuelle).
  4. Gérer le tour : la liste des retardataires exclut le bénéficiaire, qui reçoit et ne cotise pas.
  5. Tout sélectionner puis Relancer par SMS : un rappel est planifié pour chaque membre.

À retenir : un membre qui a désactivé les SMS de rappel dans son profil ne reçoit pas de relance. Les confirmations de paiement, elles, lui sont toujours envoyées.

4NavigateurGestionnaire · 1 min 04

Encaisser, valider et vérifier l'audit

  1. Se connecter sur http://localhost:3000 avec le compte d'Awa. Le tableau de bord montre le tour en cours et les membres.
  2. Paiements : choisir le membre, vérifier le montant, saisir la référence du reçu, puis Enregistrer. Le paiement est créé en attente.
  3. Après vérification de la preuve, Valider : il passe à confirme avec une référence CASH-….
  4. Si la preuve ne convient pas, Rejeter avec un motif (obligatoire). Le membre redevient « à payer ».
  5. Audit Trail : chaque action (création, saisie, validation, rejet) avec son auteur. Le bandeau vert confirme que la chaîne SHA-256 est intacte.

5TéléphoneMembre · 56 s

Le membre voit son paiement confirmé

  1. Fatou se connecte : le tour n°1 indique 1 paiement sur 3 et son badge est passé à Payé.
  2. Payer ma cotisation rappelle la marche à suivre : remettre le montant au gestionnaire, qui l'enregistre puis le valide.

À retenir : le membre ne déclare rien lui-même. Seul ce que le gestionnaire a validé apparaît comme confirmé.

Questions fréquentes

Le téléphone affiche « Erreur réseau » ou « Erreur serveur (504) »

Vérifiez que l'API tourne (make api) et que les ports sont redirigés : adb reverse tcp:5243 tcp:5243. La redirection se perd quand le câble USB est rebranché. L'application contourne désormais le proxy imposé par certains opérateurs (APN Orange) pour les adresses locales, ce qui provoquait l'erreur 504 en données mobiles.

Je ne reçois pas le code OTP

En développement, un faux fournisseur SMS écrit les messages dans les logs de l'API. Utilisez make otp TEL=+226XXXXXXXX pour afficher le code en cours (valable 5 minutes).

Comment donner le rôle de gestionnaire à un compte ?

Un compte qui s'inscrit est Membre. Pour le moment, le rôle se change avec scripts/demo.sh role +226XXXXXXXX Gestionnaire. Un écran d'administration est prévu.

Le paiement Mobile Money n'apparaît pas

Il est désactivé par défaut (Features:MobileMoney à false), puisque dans le modèle retenu l'argent reste hors de l'application. Il pourra être réactivé plus tard.

Limites connues de cette version
  • Le volet Projet collectif (paliers d'engagement, paiements partiels, report du trop-perçu, baisse de palier soumise à validation, dépenses) et l'adhésion à une tontine déjà démarrée ont été ajoutés après le tournage : ils ne sont pas encore filmés ici.
  • La validation est faite par le gestionnaire ; un rôle Trésorier distinct est prévu en phase 1.
  • Dans la vidéo web, la carte « Paiements confirmés » affiche « sur 4 » : le bénéficiaire était compté à tort. C'est corrigé depuis (« sur 3 »).
  • Deux paiements saisis exactement au même instant sur une même tontine pourraient créer une bifurcation dans la chaîne d'audit (verrou prévu avec le registre commun).
